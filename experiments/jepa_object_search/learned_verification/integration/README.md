# 验证动作与原生导航接口

`LearnedVerificationFrontier` 在现有探索代理上接入两种复看入口。对已登记目标，先走原有的现场确认流程，需要补充证据时才规划新的可达视点。上层把已定位的候选判为 `UNCERTAIN` 时，为该候选追踪一次独立复看，返回新图、原候选编号和新帧号。如果新图未写入地图，上层只收到图像，不会误用其他帧的编号。多个存疑候选各自保留源图，不共享登记状态。

地图先检查可通行区域、通向目标的视线及可用步数。模型比较可执行路线的预计证据质量。遇到确实走不动的边，将它临时排除并在余量内改选。已登记实例在路上就能提前确认。存疑候选如果在途中出现更大、与参考外观一致的独立检测框，可提前回传新图，节省余下动作；到达预定机位时也会回传新图。两种情况均须上层重新审图。过期、无定位或受阻的线索保留原审核状态。

## 项目入口

在装有 MOST-Nav、项目已有地图与证据链、Habitat、场景和本地权重的服务器项目根目录运行。训练文件和仿真数据的准备方式见各模块目录。实验目录在服务器称为 `jepa_reid_v25`。

```sh
source jepa_reid_v25/integration/environment.sh
"$MOST_EVAL_PYTHON" -B -m unittest -q test_verify_action test_confirm_view test_candidate_evidence test_scout
"$MOST_EVAL_PYTHON" -B "$NAV_ROOT/jepa_reid_v25/integration/physical_trial.py"
```

- `run_agent:LearnedVerificationFrontier` 为导航入口。默认用局部 JEPA 验证头。设置 `JEPA_UNCERTAIN_HEAD=context`，可让经过上层明确标为存疑的候选启用上下文头，已登记实例继续走局部头。单凭框小不能判定框错。
- `JEPA_VIEW_CHECKPOINT` 与 `JEPA_UNCERTAIN_CHECKPOINT` 可分别指定模型文件。直接监督权重在各训练目录生成，使用与该头匹配的同一输入格式。
- 设置 `NAV_SOURCE_SCOUT=1 NAV_LOCAL_BOXES=1` 可加入候选筛选。候选框和属性得分用于选择交给上层看的证据，最终上报沿用项目的实例确认流程。

## 物理回放

在同一时钟场景以相同登记框、局部地图、里程计和最多 12 个动作，分别注入正确参考框、错误参考框和当前检测缺失，统计模型是否上报。

| 选位方法 | 正确框 | 错误框 | 无当前检测 |
|---|---|---|---|
| 返回参考相机、局部 JEPA、局部直接监督（三组结果相同） | 报告 | 误报，距离裁判偶然给分 | 暂缓 |
| 上下文直接监督 | 报告 | 暂缓 | 暂缓 |
| 上下文 JEPA | 漏报 | 暂缓 | 暂缓 |

上下文 JEPA 选了新角度，正确框一组走了 12 步，终点还有 2,798 个目标像素，但新观测未通过实例匹配。单个场景不足以判定各策略相对优劣。回放采用实际渲染与移动、预输入定位和受控几何，同时记录源框身份、目标像素、动作与最终上报。[五组物理结果](physical_results.json) · [时钟实际历史错例](../hardcase/README.md)

## 存疑候选的送审

在同一回放中预输入上层判断 `UNCERTAIN`，分别给两个验证头正确和错误的源框。当前画面看不到源框对应的真钟。正确框一组，局部头用了 11 步，新图出现 3,710 个该实例像素；上下文头用了 6 步，新图出现 3,218 个。四组均无碰撞，都把原候选编号、到达时的新帧号和对应的新图交回审核，逐字节核对通过。没有一组自动登记或上报。该项只测取得新证据及正确送审，第二次上层判定未调用。[真实动作及新帧验收](uncertain_physical.py) · [四组统计](uncertain_physical_results.json)
