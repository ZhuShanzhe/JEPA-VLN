# 多实例寻物的候选框和跨视角确认

同一张 Habitat 图像分别交给 MOST-Nav 原生 SAM、当前 Grounding DINO，以及在 DINO 上训练的边框精修头。SAM 分割整张图，DINO 根据目标类别提框。三者的候选统一由冻结的本地图文模型 CLIP 排序，上层每次可以查看相同数量的框。

## 同样的送审名额下，哪种方法框得更好

HSSD 有 16 栋训练精修头时留出的房屋，288 张仿真图中有 244 张包含目标，合计 661 次目标出现。每张有目标的图中，任一送审框与同类别目标的可见外接框交并比（IoU）达到 0.50 即算该图命中。最后一列按同帧一对一匹配统计，代表无需排序就能从整个候选池中挑出正确框的上限。

| 候选来源 | 生成框数 | 只看首框，命中正例图 | 最多看三个框，命中正例图 | 全部候选可覆盖的目标出现 |
|---|---:|---:|---:|---:|
| MOST-Nav 原生 SAM | 6,499 | 109/244（44.7%） | 159/244（65.2%） | 355/661 |
| 当前 Grounding DINO | 557 | 183/244（75.0%） | 210/244（86.1%） | 338/661 |
| DINO 加训练的精修头 | 557 | 184/244（75.4%） | 210/244（86.1%） | 338/661 |

仅 SAM 框到的目标出现有 93 次，仅 DINO 框到的有 76 次。原生分割能补充候选，但背景区域也占用审核名额。精修头在 10 栋房屋训练、6 栋校准，用 RGB 边界和纹理调整既有框的四条边；校准最优为原框，另测的最佳非零强度为 25%。留出房屋的实例命中总数持平。当前默认使用 DINO 生成自动候选，并保留 MOST-Nav 上层原有的 SAM 掩码选择能力。[分组与房屋间差异](compare/README.md) · [原生 SAM](sam/README.md) · [边框精修训练](refine/README.md)

## 为什么近距离看到时钟仍未确认

在两个 HM3D 开发场景重新截取 43 张图，覆盖历史机位和朝向指定目标的机位。重新核对时钟复看终点，仿真的同一实例编号同时落在挂钟和木台面上。过去记录的 5.01% 以全部 17,968 个同编号像素为分母。钟面对应的两个分量共有 905 个像素，DINO 首框包含其中 901 个。两台相机的位置、方向和视场均已核对。在独立的 RGB 外观检查中，原版 SAM 和 DINO 的首框与终点可见钟面分别达到 0.936、0.976 IoU。这个机位的钟已被框住。[仿真采图与像素核对](habitat/README.md) · [匿名 RGB 外观检查](refine_blind/README.md)

将历史登记框或各方法重新选出的首框交给同一套实例确认逻辑，三种方法用原图确认原图都通过，用靠近后的新图确认先前登记的实例都返回 `no_current_instance_match`。在这个案例中，下一步应检查小幅登记图和近景之间的实例匹配。画作场景也包含四张旧路线的图，指定画作在这四帧中均未达到可见门槛。提框首先需要路线获取目标的有效观测。[上下游接口与对照](adapter/README.md)

这组结果评估图像定位和一次跨视角复核。没有使用付费上层模型，也没有运行新的整回合导航评测。
