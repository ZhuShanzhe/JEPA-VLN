# 到了报告范围，现场能否看见目标

这三次机会来自 V8 联合模型在真实改道期间第一次进入、随后整回合均未获正式记分的实例。两扇白门属于同一回合和同一个起点，灯属于另一回合。所有动作替代方案均在冻结的历史轨迹上离线重放。这里的“可见”按同一实例的语义像素计数；读出门的颜色、区分灯的类型仍需要实际的图像识别。

| 对象 | 首次入围步 | 连续入围状态数 | 原地水平转向的最佳像素数 | 最多 8 个前进/水平转向动作，且终点仍符合报告距离 |
|---|---:|---:|---:|---|
| 白门 A | 124 | 11 | 0 | 0 像素 |
| 白门 B | 124 | 11 | 0 | 0 像素 |
| 灯 | 119 | 17 | 0 | 第 4 步可见 191 像素；第 6 步可见 657 像素 |

原地转向以真实朝向为起点、30° 为间隔转满一圈，使用与 RGB 对齐的 320×320 语义镜头、120° 水平视场。两次原地转向可达的五个水平朝向，在上述每个连续入围状态也都渲染了同一实例；结果全部为 0。三例按完整回合累计入围的状态数分别为 16、16、24。不同状态可能处于同一位置。

灯的四步见证路线是右转、前进、右转、前进，两个 0.25 米前进命令产生约 0.48 米净水平位移。再前进两步可以见到更大的目标区域。两扇门所在起点穷举了 866 个可达位姿，其中 584 个仍在对应实例合法范围。灯的起点穷举了 1,465 个位姿，其中 1,249 个仍在该灯的合法范围。位姿以位置和朝向按十万分之一量化去重，碰撞和原地动作消耗相同步数。搜索使用真值选择最优路线，只衡量在给定动作集内存在的机会。

另在原位允许左转、右转、抬头、低头，每个动作 30°，最多 8 步。白门地点核验 122 个可达姿态，灯地点核验 119 个，三个实例像素仍均为 0。行走与俯仰混用的序列未穷举。最后从正式起点重放此前的真实轨迹，再用官方环境逐步执行灯的两条见证路线，重复获得 191、657 像素且均处在该实例的合法报告范围。是否发出合格报告仍由导航模型决定。

## 独立视点核对

| 对象 | 到最近官方视点的可走距离 | 在该视点按标注朝向观看的实例像素 | 到最近一个按标注朝向可见至少 103 像素的视点 | 该处像素 |
|---|---:|---:|---:|---:|
| 白门 A | 0.182 米 | 0 | 0.374 米 | 856 |
| 白门 B | 0.182 米 | 0 | 2.820 米 | 180 |
| 灯 | 0.207 米 | 0 | 0.484 米 | 126 |

最近视点均与机器人同高，按官方导航网格可走距离都在 0.25 米阈值内。每个实例都有另一些标注视点能渲染出该实例；三例分别取得 6,238、2,358、820 像素的正对照。将上表第一次满足 103 像素的参考相机朝向直接移至原地，白门 A 得到 1,981 像素，白门 B 和灯仍为 0。这些参考朝向可包含倾斜，连续角度也未必能用离散的 30° 转向命令达到。

数据按官方实例 ID、HM3D 描述表和模拟器实例注释三者绑定。两个回合全部原始动作位置的最大重放误差为 0 米。两个首次入围时刻与已保存实际 RGB 的平均像素差分别约为 0.232、0.224（8 位灰度级，按 RGB 各通道和 64×64 缩略图平均）。[逐例脱敏汇总](turns.json)
