# JEPA 选路与 MOST-Nav 跟随器的离线验收

当 JEPA 在 MOST-Nav 提供的候选中改选另一条路线时，执行适配器接管从当前位置到两条路线首个不同动作的短前缀。每步都从原版探索跟随器返回，下一帧回执与已下发动作一致后才推进。收到首个不同动作的回执后，原版跟随器继续追踪选中的航点。原生报告、结束、换目标、路径失效或前进受阻都会结束本次交接。收到新建图锚点后，若位置校正超过 0.25 米或朝向校正超过 20°，跟随器使用校正后的原生建议。这两个阈值属于接口参数。

## 已有 HM3D 场景中的实走

在[五例 V13 整机记录](../most_environment_panel_v13/README.md)中，有两个回合产生了评分。逐一恢复其中全部五次评分前的仿真姿态，送入归档候选几何和选路结果。两条分支由同一位置和朝向出发，在 Habitat 中实走，通过位置、朝向与下一帧收到的动作核对是否分岔。实时 SLAM 更新和上层决策使用离线输入。交回控制后，两条路线各由原版跟随器继续走三个动作。

四次改选全部抵达分岔，沿用原案的一次保持相同轨迹。五次交接后共执行了 15 个后续动作。另一个 HM3D 工程场景使用冻结的七份权重文件完成取景与推理。冻结模型在该输入下沿原路线前进 0.25 米，仅注入另一选择时，机器人实际左转了 30°。13 项宿主回归覆盖了碰撞、报告抢占、位姿校正、回执不符、重置和动作预算边界。另经原版公开入口 `act()` 检查了三种情况：正常改选、报告抢占和结束抢占。全部验收使用离线输入，付费请求为零。本组证据衡量单次选路能否生效；完整回合的寻物成绩、真实上层抢占和在线建图校正频率仍待独立评估。[物理回放摘要](physical_summary.json) · [冻结权重验收](rank_summary.json) · [原版 act 调度验收](act_summary.json)

## 入口与复跑

服务器数据盘项目目录为 `/root/autodl-tmp/jepa_object_search`。适配器入口为 `jepa_exec_agent:JepaExecutionFrontier`。它依赖已部署的 `jepa_env_v13/most_integration`、本地训练权重、已获许可的 MOST-Nav 和 HM3D。冻结评分器沿用三个 24 步候选的输入格式；执行器只控制到首个分岔。

```sh
cd /root/autodl-tmp/jepa_object_search
bash jepa_exec_v14/check_offline.sh
```

脚本在数据盘创建独立的验收目录。历史回合、逐步位姿和仿真资产保存在服务器。仓库收录执行适配器、测试源码及汇总数据。
