# 已见实例的观察位姿与报告确认

当 MOST 注册一个经过审核、具有三维位置的实例时，系统按原生规范实例 ID 关联其观测记录。保存的观察线索包括关键帧编号、该帧中目标中心附近的灰度外观，以及可以由建图服务重新定位的相机位姿。未归属的重复候选、缺少像素中心和过于平坦的图像块不会进入外观记忆。

原生高层做出探索或访问实例的决策时，控制器优先检查仍未上报的实例。若存在可定位的观察帧、该帧与实例估计水平距离不超过 2.25 米，且未超过重访次数和冷却限制，控制器调用 MOST 的地图规划器返回曾实际拍摄该图的位置。靠近时对齐观测方向，并把当前 RGB 与原注册证据交给原版 VLM。跨回环重规划时按关键帧编号重新读取相机位姿。

原 VLM 发出报告命令时，有外观模板的实例需要同时通过当前视觉重识别和地图距离检查。距离门槛采用原本对近邻上报的距离，或机器人回到距观察点 0.65 米内且取证点距实例中心不超过 2 米。图像匹配在多个尺度搜索登记点附近的局部纹理，并检查最佳位置和第二位置能否区分。模板不充分时，沿用 MOST 对当前图像的原生决策。去重和正式报告由 MOST 的同一实例账本执行。上述距离是当前地图的估计量，裁判独立按真实可达视点判定。

缺少可靠实例时，从原生前沿中评估能抵达的观察位置。对每条路线截取仍在可通行区域内的动作，计算预期新见区域，使用原有 JEPA 证据模型对这些前缀排序。首次不同动作的执行、碰撞和地图更新沿用既有底层接口。每个任务上限 300 个动作，扫描和返回均占用预算。

| 文件 | 功能 |
|---|---|
| `confirm_agent.py` | 原生回访规划、活体图像复核、上报账本与事件 |
| `view_memory.py` | 从关键帧提取目标区域以及当前帧匹配 |
| `view_explore.py` | 利用当前地图和 JEPA 挑选可达观察位置 |
| `confirm_check.py`、`view_check.py` | 禁网验证正负报告、原生去重、返回优先级和可达视角 |
| `view_receipt.py` | 对照规划的相机位置、朝向和实际重放结果 |
