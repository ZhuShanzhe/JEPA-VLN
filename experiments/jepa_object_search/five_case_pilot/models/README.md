# JEPA 多实例寻物路线头

`route_heads.py` 在导航器已经选定“探索前沿”后，对它给出的合法路线做二次排序。V5 根据候选动作预测未来会看到的局部视觉特征，V6 在历史视角稀疏时预测同一目标。导航器继续负责建图、提出候选、移动和报告实例。

## 输入

代码依赖 PyTorch。推理需要 V5、V6 两份训练后的权重，以及外部冻结的 OpenCLIP RN50（OpenAI 预训练）图文编码器。此目录提供路线头源码和核验回执。对齐原实验时使用下列输入。

| 输入 | 约定 |
|---|---|
| 历史观测 `views` | 字典，键为相对当前机身的朝向格。0 表示正前方，逆时针每 30° 加 1，模 12。值是同一 RGB 画面的整图、左裁剪和右裁剪的 RN50 特征，形状 `[3, 1024]`。每个裁剪是边长为较短边 65% 的正方形，垂直居中并贴左缘或右缘。三个图像独立经过官方 RN50 预处理和 L2 归一化。在线原实现以 FP16 缓存这些特征，送头前转为 FP32 并再次归一化。|
| 视图来源 `steps_seen` | 与 `views` 同键，值为该图的实际观测步数。每个朝向保留最近的帧，从拍摄以来累计前进指令长度最多 0.5 米。只传入已拍摄的视图。原实验将可校正的摄像机画面按实际内参重采样为水平 90° 方形视图。|
| 文本 `text_vector` | 形状 `[1024]`。去掉任务数量及寻物指令前缀后，以 `a photo of a <目标短语>.` 作为 RN50 文本输入，保留属性词，使用归一化后的 FP32 特征。|
| 路线 `plans` 与 `original` | 当前候选的名义动作序列列表，原选择为从零起的列表索引。宿主动作 1 为前进 0.25 米，2、3 为左、右转 30°。内部预测器采用 0、1、2 编码。|
| 相机 `pitch` | 原宿主的俯仰偏移步数。0、1 对应本实验可校正的两个角度。其他值沿用原选择。实际接入其他相机时应先标定内参和俯仰角。|

## 推理

```python
from route_heads import load_heads, rank_routes

heads = load_heads(full_weights_path, sparse_weights_path)
decision = rank_routes(heads, plans, original, views, steps_seen, text_vector, pitch=0)
chosen_index = decision["selected"]
```

每个替代路线与原路线取双方共有的最长已训练时长，可取 4、12、24 步。对两个动作前缀完全相同的路线跳过比较。一个前缀预测中点和终点，各输出三个局部特征，单路输出形状为 `[2, 3, 1024]`。

- **V5** 在至少有三个近处历史朝向，且待比较两条路线的中点和终点所需朝向都能在已见视图的 30° 内找到时启用。存在这样的路线对时，只比较有覆盖的路线对。
- **V6** 在上述覆盖条件未满足、但有当前朝向观测时，从正前方沿一侧选择 1–3 个连续已见朝向。预测器显式读取与所需方向的角差和缺失标记。
- **保留原选择**适用于没有不同的合法计划、缺少当前视图或相机角度不适用的窗口。预测路线与目标词在六个特征上的相似度经过平滑最大值汇总；替代路线必须比同一时长的原路线高出 0.01 才改选。`observed_selected` 使用方向最近的历史图文特征执行相同的比较，供观察基线对照。

## 训练信号

同一起点的每条候选路线都要留存已观察 RGB、预先生成的动作前缀、实际执行后中点与终点 RGB，以及各目标词对应的分支可见性增益。按房屋划分训练和验证。真实未来 RGB 只在训练时提供目标特征，推理时由动作条件预测器给出。

V5 在训练房屋的已见特征上拟合 64 维 PCA 子空间，在其中学习未来相对已见方向的残差。训练损失为未来区域余弦误差，加 0.5 倍同一起点各路线中心化预测误差，再加 0.20 倍目标条件成对排序损失。排序损失按真实可见性增益差加权，只使用差值大于 0.005 的候选对。V6 从 V5 初始化，在训练时遮掉其余朝向，仅留下 1–3 个连续视图，未覆盖方向的余弦误差权重乘以 1.35。两条路线头都使用冻结的文本特征评分。

### 从本地缓存训练

`train_heads.py` 直接读取用 `torch.save` 保存的字典列表。每个字典是一处起点在一个固定动作时长的全部候选和查询。下例中，`N` 是候选路线数，`Q` 是目标查询数，`H` 取 4、12 或 24。输入张量可由有权使用的场景和冻结编码器离线生成。

```python
record = {
    "sid": start_id, "house": house_id, "split": "train",
    "step": 0.25, "turn": math.pi / 6,
    "context": panorama_clip,             # [12, 3, 1024] 每个朝向的整图、左图、右图
    "yaw": torch.arange(12) * math.pi / 6,
    "actions": legal_prefixes,            # [N, H] 0 前进，1 左转，2 右转
    "future": actual_future_clip,         # [N, 2, 3, 1024] 动作执行至 H/2、H 时的特征
    "queries": target_phrases,            # 长度 Q；顺序与 text、gain 的目标维一致
    "text": normalized_clip_text,         # [Q, 1024]
    "gain": measured_visibility_gain,     # [N, Q] 各分支相对观察历史新增的目标可见证据，0–1
}
torch.save(all_records, "features.pt")
```

原实验在 HSSD 的 12 栋训练房屋采集 144 个起点。另 4 栋开发房屋共 48 个起点，2 栋作为 `calibration` 选择权重，2 栋作为 `check` 复核。后续迁移检验另用 4 栋房屋。每栋房屋只属于一个划分。训练使用同一物理起点的配对路线和观测历史生成的实例可见性增益，包含自然探索及扣除观测历史中已确认实例后的增益标签。训练头的输入始终只用已见全景、计划动作和目标词。

```bash
python train_heads.py --cache features.pt --output v5.pt
python train_heads.py --cache features.pt --output v6.pt --full-weights v5.pt
```

| 设置 | V5 全视野头 | V6 稀疏头 |
|---|---|---|
| 优化器 | AdamW，学习率 0.001 | AdamW，学习率 0.0005 |
| 轮数与批次 | 12 轮，每批 12 个起点–时长组 | 9 轮，每批 10 个起点–时长组 |
| 可见历史 | 全部 12 个已见朝向 | 每组随机保留 1、2 或 3 个连续朝向，以当前视野结束，左右侧由轮次和起点标识的哈希决定 |
| 模型选择 | 每 3 轮比较一次，按房屋等权，最大化两倍正确目标净增益减去错词净增益 | 每 3 轮比较一次，在需要预测未见方向的校准样本中，最大化正确词净增益相对最强对照的优势，对照包括保留原候选、错词和直接匹配已见方向 |

两阶段各自重置随机种子为 23，使用 CPU 双线程、确定性运算和范数上限 3 的梯度裁剪。校准时对同一起点的不同目标词做固定置换，假设每条合法路线等概率作为原选择，分差严格大于 0.01 才改选。这个候选参照与闭环中 MOST-Nav 的实际选择有不同分布。命令行会打印选中的轮次和每次校准值，输出的权重可直接交给 `load_heads`；`check` 标签只参与房屋互斥检查。

## 核验

`parity.json` 记录对同一个真实 HSSD 验证起点的六种输入条件。使用服务器上的原始 V5、V6 权重，单独检查全视野、稀疏视野和保留原选择三种路径。各个实际评分条件下，预测区域特征和路线评分与实验实现的最大绝对差均为 0，选路结果与已见视图对照的选路结果分别一致。

`training_parity.json` 记录 PyTorch 2.8.0 的 CPU 反向传播核验。V5 的 12 组真实训练样本与 V6 的 10 组真实训练样本分别对齐原脚本；两个批次的 FP32 损失逐值相同，全部参数张量的最大绝对梯度差小于 `2e-9`。

使用原始本地缓存运行上述两个完整训练命令，也分别选中了原实验的第 3 轮和第 9 轮。与研究脚本存档相比，训练后两份权重的逐参数最大绝对差分别为 `5.22e-7` 和 `1.52e-6`。
