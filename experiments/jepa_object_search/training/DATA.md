# 训练输入与离线标签

一行索引对应一个“历史观测、查询、报告记忆、候选路线集合”。相同路线在变更查询或报告记忆后可以有多行。行数不能换算成独立起点数或物理轨迹数。

| 来源 | 在线输入 | 离线收益标签 |
|---|---|---|
| HSSD 先导分支 | 12 帧转向观测、基于局部已知空间生成的候选、24 步名义动作、类别查询 | 将于不同连续相机位姿看到的同一实例的两帧像素数取较小值，再求时间最大值。256×256 图像下，8 像素及以下记 0，128 像素及以上记 1，中间线性插值。对每个实例取分支相对前缀的证据正增量并求和。该量可以大于 1。 |
| HSSD 与 Blender 的报告历史 | 实际绕行、拍摄与返回得到的报告图像和相对位置，已构造的报告事件 | 同起点交换已有报告，离线核验哪条路线可以看到另一个合格实例。报告事件属于受控实验。 |
| Blender 颜色配对 | 起点 RGB、可执行路线、查询；变更颜色布置及查询 | 离线读取目标掩膜的颜色。颜色提示特意与目标对应，这组样本只验证接口。 |
| 独立 Blender 房屋 | 起点 RGB、候选计划与查询 | `replay_bays.py` 在同一起点的两条实际路线采集未来 RGB。区域存在标签来自受控对象布置，途中持续曝光由实例掩膜测量。 |

`label_regions.py` 为 HSSD 派生独立的区域存在监督。源场景中与查询匹配的对象资产及数量必须与回放所用的实例库存一致。一条候选的名义前沿和实走末端需落在同一个新的、唯一可归属的区域。区域归属要求足够的高度与平面余量，目标放置使用标注对象位置。缺少分类、边界模糊或不满足条件的候选保留未知值 `-1`。模型训练只在标签为 0 或 1 的候选上计算此辅助损失。这些标签只涉及已标注实例范围。

## 数据契约

`index.jsonl` 字段包含唯一记录编号、来源、房屋、训练或开发划分、查询、收益标签类型、相对 NPZ 路径和内容 SHA-256。`receipt.json` 记录索引指纹和分组计数。每栋原始 HSSD 房屋及每个 Blender 基础布局独占一个划分。

| 字段 | 含义 |
|---|---|
| `context`、`memory`、`memory_xy`、`has_memory` | 当前观测特征、过去报告帧特征、相对位置及其可用性。缺失记忆使用全零并显式关闭。 |
| `xy`、`actions`、`step_m`、`turn_deg` | 执行前合法路线的前/左坐标（米），名义动作 0 前进、1 左转、2 右转，米制步长和转角。 |
| `future`、`gain`、`region_presence` | 候选实走后的教师视觉特征、按来源定义的收益和区域存在标签。仅用于训练监督与离线评估。 |

## 生成顺序

在服务器数据盘准备现有 `frontier_jepa`、HSSD、Blender 回放和本地冻结 V-JEPA 2.1 权重。使用含 `torch`、`numpy`、`Pillow`、`timm` 的既有视觉环境。以下命令在已安装项目的运行根目录执行，脚本目录用 `KIT` 指定。每次构建使用新的输出目录，全部校验通过才以最终目录名发布。

```bash
PY=/root/autodl-tmp/jepa_instance_bench_20261016/jev_vision_env/bin/python
KIT=/root/autodl-tmp/jepa_object_search/training_round1_20261115/kit
export CUDA_VISIBLE_DEVICES="" OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=1
"$PY" "$KIT/data_prep.py" --root "$PWD" --output training_ready/data/core_v1
"$PY" "$KIT/label_regions.py" --root "$PWD" --base-pack training_ready/data/core_v1 --output training_ready/data/core_region_v2
"$PY" "$KIT/data_prep.py" --root "$PWD" --base-pack training_ready/data/core_region_v2 --extra-raw training_round1_20261115/bay_raw --output training_round1_20261115/pooled_mixed
"$PY" "$KIT/data_prep.py" --root "$PWD" --base-pack training_round1_20261115/pooled_mixed --extra-raw training_round1_20261115/bay_cues --output training_round1_20261115/pooled_final
```

核心包使用四个等距 RGB 帧经冻结模型获得的全局平均特征；分支未来帧不进入在线模型输入。局部特征版本使用单独缓存。HSSD 开发集在连续证据增量下有 11/48 个起点的分支收益不同（覆盖四栋房屋），原先“一次入镜即算新增”的二元标签有 2/48。修改监督定义不会增加独立轨迹数量。

## 同一输入的适用边界

每批原始渲染保留各自的索引。合并时先核验原包的索引和每个文件的 SHA-256，再将新增记录送入同一冻结编码器。新记录按全局唯一的 `id` 识别，冲突或跨训练/开发的房屋会使合并失败。合并只读已有包，向新的目录写入。额外渲染记录在每个原始索引中按 `id` 查找，路径相对于其来源目录。

在隐藏目标互换组，六个 Blender 基础布局提供 48 行查询、96 个候选条目。每个查询的两个实际结果均有差异。用 `audit_observability.py` 按同一房间、查询、起点 RGB、候选坐标和计划动作精确分组，得到 28 种可见输入。其中 20 组在输入相同的情况下有互斥的最优方向，涉及 40/48 行，其中包括开发集全部 16 行。相同输入的确定性策略无法同时答对这些互换样本。这组数据可检验遮挡条件下的预测误差与置信度；有有效曝光差只代表事后两个分支结果不同。先验依赖有线索的样本和自然 HSSD 数据另行计分。

真实 HSSD 标签为空的候选不参与区域存在损失。在原自然开发样本中，有明确区域标签的 6 个候选均为负例。仅用这批开发房屋不能估计区域存在预测对正例的召回率。受控的视觉线索能验证模型是否响应查询，但基于人造线索获得的选路成绩不能代替自然房屋的泛化成绩。

有线索的 Blender 组在相同六个基础布局中摆放灯具或咖啡台作为上下文，只修改线索与目标的对应布置。24 个查询中有 16 个训练、8 个开发，起始视野中目标像素均为零。24 个输入均有不同的实际分支收益，调换目标后观测随线索改变。这组与隐藏互换组分开统计。
