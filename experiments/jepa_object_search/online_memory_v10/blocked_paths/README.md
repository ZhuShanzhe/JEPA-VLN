# 重访通道的可通行性

这个实验检验一件事：原先走不通的方向在门重新打开后，系统能否恢复探索，同时保留死胡同入口处仍可到达的物品。

## 场景与输入

Blender 生成 14 套走廊，分别用 8 套训练、2 套验证、4 套独立测试。每套布局含两条通道。机器人先分别探入两侧，再退回起点。一侧关闭、另一侧开放。随后门保持原状，或两侧交换开闭状态。两种条件下都会移动与通行无关的物品。Habitat 重新计算可行走区域，实际执行动作检验通道。中立朝向在事件前后的 RGB 完全相同，机器人需要重新转头观察。

可通行性更新头比较同一方向的历史 RGB 和当前 RGB，输入还包括预算为 4 步或 12 步，以及之前执行动作时 RGB 所反映的位移。它学习过去的通行判断在当前是否应当反转。另设只看当前 RGB 的同容量模型、按训练集频率的固定先验、沿用过去碰撞记忆、整侧禁行，以及仅比较新旧图像平均像素差的基线。距离、实例掩码和门的开闭状态仅用于仿真与评分。

## 留出布局

| 评测项目 | 样本 | 更新头 | 历史碰撞 | 当前 RGB | 像素差阈值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 判断 3 米路线能否走完 | 32 | 32/32 | 16/32 | 30/32 | 32/32 |
| 通道刚重开 | 8 | 8/8 | 0/8 | 8/8 | 8/8 |
| 通道刚封闭 | 8 | 8/8 | 0/8 | 7/8 | 8/8 |
| 保留封闭通道内、1 米预算可达的目标 | 16 | 16/16 | 16/16 | 16/16 | 16/16 |
| 两条 3 米路线中选可通过的一侧 | 16 | 16/16 | 8/16 | 16/16 | 16/16 |

历史碰撞仍按候选路线的步数计算。如果只要过去在该侧遇过障碍就排除整侧，近处目标的保留数会从 16 降到 8。该实验支持重访更新和按动作预算估计可达性。简单像素差规则在这四套布局上同样满分，单靠当前 RGB 也选对了所有较远路线。现有结论仅覆盖受控通道；真实住宅、视角变化和完全未观察的死路仍待验证。

## 复现

对留出布局 h10 的四个回合进行了独立重放。两次的 RGB、历史运动观察与物理结果完全一致，见 [物理重放记录](physical_replay.json)。

1. 用 Blender 在后台执行 [build_corridors.py](build_corridors.py)，以私有实验目录下的 `assets` 为输出位置。
2. 在 Habitat-Sim 环境用 [physical_probe.py](physical_probe.py) 依次运行布局编号 `h00` 至 `h13`。每个编号生成四个回合，公开源码可重新生成图像和评分标签。
3. 在含 NumPy、OpenCV 和 scikit-learn 的环境运行 [calibrate.py](calibrate.py)。脚本按固定分屋训练更新头与当前 RGB 对照，随后评估三组划分。权重存于研究服务器。完整汇总见 [results.json](results.json)。
