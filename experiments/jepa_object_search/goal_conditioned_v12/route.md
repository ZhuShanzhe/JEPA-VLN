# 多实例寻物的系统开发路线

**目标是在相同移动预算内，让机器人发现更多此前没有看清的目标实例。** MOST-Nav 继续建图、提出前沿、执行移动和管理报告。选路头只在存在多个可达探索方向时接管排序。性能以沿途首次见到的不同实例、完整任务中正确报告的不同实例和完成配额的步数衡量。保留当前可用策略，每轮训练给出一个可载入的替换件和回退条件。

| 优先级 | 要解决的具体问题 | 训练或接入方式 | 交付标准 |
|---|---|---|---|
| 1．目标不同，路线也应不同 | 同一分岔找椅子和找灯需要转向不同房间，模型却容易总走开阔的一边 | 在 HSSD 训练房从同一位置实际走三条路线。取目标实例首次出现时的局部视觉特征，训练目标条件 JEPA；对必须走不同方向的目标对，要求交换目标词后正确路线也交换 | 首选模块可从三个实际 RGB、目标词和等预算计划输出候选得分。保留旧模型的几何与探索能力，校准达标才启用新的目标修正 |
| 2．走过以后改选更有机会的路线 | 探查过的方向可能是死路，也可能还有另一个尚未发现的同类实例 | 回合内记忆记录访问位置、碰壁和实走方向的目标线索。以走第一条、实际返回、再走另一条后**新见实例 ID 集合**监督二选；对重复看到的同一实例只记一次 | 共享在线记忆始终工作。学习得到的更新幅度在校准房屋上确定，和同一首选、同一预算的原记忆比较后评估是否接入 |
| 3．先验能修正，没线索时继续探索 | 摆放习惯过强时会忽略反常位置。单从相同入口画面无法判断哪个分支藏着目标 | HSSD 学习自然分布。Blender 用同一入口做反常摆放、无提示或多实例成对干预；有可见提示的样本训练首选，无提示样本优先训练获得新观察后的改选。按房屋及类别划分，单列提示不足场景 | 选路接口支持有限度的偏好调整。物体不可见或先验不可靠时保留默认探索，只有碰撞或可达性检查证明不可走才排除路线 |
| 4．让分岔收益传递到整机 | 在近处看见物体以后还要接近、去重、正确上报 | 用真实 MOST-Nav 前沿构造动作计划，为实际可行候选评分并返回原前沿编号。缺少相机朝向或合格候选时沿用原策略。按完整导航日志定位未曝光、可见未确认、重复报告三类损失 | 在同一起点、查询、预算的完整任务中比较实例召回、配额完成率、重复报告和每个有效新实例的步数 |

开发中优先解决错误带来的损失。校准房用于挑选模型与控制接管强度；已经打开成绩的房屋保留为回归案例。新的未用房屋用于判断改进能否迁移。线上记忆在一个任务内持续更新，跨房屋经验由后续离线训练吸收，避免把某栋房屋的偶然摆放当成通用规律。
