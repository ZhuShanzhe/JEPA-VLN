# MOST-Nav 接口与 Habitat 实际接线

**接入位置。** 在 MOST-Nav 已经选定“继续探索”、地图已生成可达 frontier 后，对候选短路线重新排序。接回原有 frontier 激活与跟随器，原有 VLM 继续负责探索、报告、结束等高层决策。核对的私有源码版本为 `bd517cf7`。当前完成了真实仿真的模块接线，完整 MOST-Nav 的调度和报告链路尚需联调。

| 主机输入或输出 | 已核对的接口 | 接线约束 |
|---|---|---|
| 可达探索路线 | `agents/nav_agent.py` 按地图 A* 局部路径归并 frontier；每个原生 cluster 带路径、尺度与标识，`agents/decision_state.py` 整理决策状态 | 在同一决策快照上用原生跟随器分别预演候选，保留候选与 frontier 标识映射。当前头要求三条不同且足 24 个动作的路线，不足时沿用主机原决策 |
| 移动与执行 | `agents/navigator.py` 的 `PathFollower` 逐步给动作；`_activate_frontier` 启动选中路径 | 主机前进、左、右编号 1、2、3，送入头的编号 0、1、2。两边前进 0.25 米、转向 30°。地图的相对尺度使用该 frontier 自带的尺度 |
| 图像与记忆 | 模型读取同一位置相对当前朝向 −30°、0°、+30° 的三张 RGB 与目标词、计划动作 | 历史图像须同位姿、在决策前已拍到。主动补拍的转向计入预算。只将实际执行过的动作、碰壁与沿途图像写入在线记忆。部署时还需处理原任务的描述词、实际相机视野与训练相机的差异 |
| 输出 | `BoundedSelector.scores` 返回三个选路分数 | 分数含探索和记忆附加项，可超出 0 至 1，不能作为校准概率。保留报告实例和任务终止的原判定 |

**真实记录核对。** 对现存的 56 个路线选择日志共 364 次决策核对。4 次具有至少三条不同的、来自原生 frontier 的 24 步计划。把每次决策前的所有轨迹帧按位置（1 毫米内）、转向与实际存档检查，3 次只有一个所需朝向，1 次有两个。没有足以直接运行本接口的完整历史时刻。[输入核查](check_recorded_inputs.py) · [汇总](recorded_contract.json)

**真实仿真接线结果。** 在 HSSD 校准划分按文件名固定首个有数据的房屋、起点与第一个目标。机器人实际转动相机取得三图、由有界 JEPA 选路、进入选中路线，在新位置重新生成三个几何可达候选，读取更新后的记忆再选一次。第一次选三号候选，行进 3.25 米；第二次选二号候选，行进 3.50 米。两次共执行 48 个探索动作及 8 次采图转向，实际搜索均无碰壁；场景中采集的 14 帧观察和 56 个动作均进入记忆。第二次有完整的新观察输入。该单回合用于接线验收，不用于推断成功率或 MOST-Nav 整机性能。[物理执行程序](physical_loop.py) · [执行回执](physical_loop.json)
