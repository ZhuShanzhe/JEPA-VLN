# 地图标定后的跨视角身份复核

当原生注册表有一条新观测、一个邻近实例，两者来自不同机位且身份仍有歧义时，缺少米制尺度会使地图距离不可靠。系统先保存这条待审观测，并允许导航继续取得新视角。等待最长四个物理动作。已有同帧证据、明确的不同实例，以及上层明确要求登记新实例时，沿用各自的原生审核路径。

获得尺度后，系统重新计算邻近实例及其距离，把位姿 JEPA 的提示连同刷新后的候选放入下一次决策输入。执行合并前再核对当前邻域。之前邻近、标定后已不在范围内的实例无法通过此次合并。正负判断均复用相同观测与地图几何的计算结果；地图几何、实例成员、观测或目标绑定发生变化后重新评估。超出等待时限仍无尺度时，交给原生视觉复核，隐去未标定距离。位姿提示的产生不会改变报告计数。

[实现](delayed_pose.py) · [边界测试](test_delay.py) · [HSSD 两对功能样例](check_hssd_delay.py) · [匿名结果](hssd_delay.json)

十个测试涵盖标定前后交错的工具调用、地图更新、已报告实例、近邻替换、超时释放和跨回合清理。两对 HSSD 留出样例沿用事先选择的真实预测框和冻结权重，将尺度晚一个动作提供给待审入口。椅子的同物观测得到 0.994 分，触发同物提示；两件相邻沙发得到 0.750 分，低于 0.941 的阈值。这项功能测试用 HSSD RGB-D 与已知位姿构造建图观测，并替代最外层工具与状态渲染，实际运行原生注册表、冻结编码器和位姿评分。导航任务成绩另由正式仿真回合衡量。
