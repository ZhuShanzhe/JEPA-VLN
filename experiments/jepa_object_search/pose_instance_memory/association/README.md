# 相邻机位的实例复核

画面中的两个同类框有间隔时，将二者记为可能不同的物体。相邻机位若分别看见两件物体，先用可见表面估计和相机位姿在两张图之间双向投影，再做一对一配对。只有两个配对都没有竞争者、且在两张图中分别分开，才拒绝将交叉组合并为同一实例。遮挡一件、丢失深度、角度跨度过大或两个框竞争同一目标时，保留不确定状态。

| 检查 | 实现 |
|---|---|
| 邻近机位 | 相机间距至多 1.25 米，光轴夹角至多 45°，滤除几乎完全相同的机位。 |
| 对应关系 | 两端的可见表面点相距至多 0.45 米，双向投影落在对方框及其小幅边缘容差内。综合比较重投影残差和三维距离。只有行、列两个方向相对第二候选都留有余量时接受。 |
| 同帧分离 | 有效框之间至少留 2 像素间隔。同一大框与内部小框、重复框均不能证明是两件物体。 |
| 实际接入 | 在原生系统，跨视角互斥只用于已经过独立审核的观测。几何可阻止一次有冲突的合并，创建实例与报告仍须经过原生审核。 |

## 留出房屋

16 栋房屋，96 组三机位图像，共 288 帧。表中未知指至少一个预测框不能按 IoU ≥ 0.50 唯一匹配到当前帧带标注的物体。各预测框单独赋予身份，以便把同一物体被检测两次的错误区分计入。不同物体在同一画面中组合计数，两帧均出镜的物体跨帧按有向组合计数。

| 普通 RGB 检测框上的判定 | 总数 | 正确 | 已知错误 | 未知 |
|---|---:|---:|---:|---:|
| 同一画面分开的框代表不同实例 | 421 | 154 | 0 | 267 |
| 仅按图像框 IoU 选同一实例 | 81 | 20 | 12 | 49 |
| 仅按三维近邻选同一实例 | 368 | 247 | 1 | 120 |
| 加入机位和双向投影，关联同一实例 | 326 | 233 | 0 | 93 |
| 两个机位都支持不同实例 | 196 | 98 | 0 | 98 |

普通预测框覆盖 4,224 个持续共现异物组合中的 95 个；相同算法用真实框可覆盖 3,110 个。相距至多 1.25 米的同款异物有 3,222 个组合；两种输入分别覆盖 49 和 2,548 个。组合数受同一高密度场景中的物体数量影响，逐房屋等权计算的持续共现覆盖率为 16.22%。真实框结果用于定位检测环节损失。[完整计数](summary.json)

## 导航入口

multiview_agent:MultiviewFrontier 继承 V20 的原生报告审核流程。运行时按 V20 的原有路径加载项目依赖，另将当前目录加入 PYTHONPATH。

- NAV_LOCAL_BOXES=1 在决策时补全实时 RGB 上的目标框。调用原生 propose_candidates 时，也可在对应的地图关键帧上运行同一个检测器。图像和点图颜色坐标校验通过后，将中心点送入原生 prepare_pixels。分割精化框与检测框吻合才进入待审核队列，还要经过原有 commit_candidates 和深度验证。非关键帧上的实时框仅作为视觉提示。NAV_BOX_DEVICE=cuda 对应本次检测评测设备。
- NAV_COVISIBLE_GUARD=1 在重复归属与实例合并两个原生入口检查几何互斥。拟合内参、位姿或尺度不可靠时，保留原审核入口。共现保护需两机位分别具备两个已经独立获得的实例观测。
- NAV_REID_POSE_WEIGHTS 指向数据盘上的 jepa_reid_v21/model/pose_jepa.pt，提供可选的位姿 JEPA 提示。使用同一 VGGT 地图快照中的位姿、尺度及可见表面点，结合两个独立物体裁剪和遮框背景。提交提示要求只有一个邻近登记实例、双帧图像与点图对齐，并达到真实检测框校准阈值。原裁决器仍可判断为新实例。

运行 bash check.sh --weights 检查19项几何、候选审核和报告接口用例，随后调用真实训练权重，通过研究策略子进程比较留出房屋的两个观测。几何计数使用 evaluate.py DATA_DIR PREDICTIONS_JSONL RESULT_JSON 复算。

## 同款邻近物体

在 8 栋房屋的 10 组布局中，把原物与放入同款第二件物体的场景配对，合计 60 帧。56 个同款近邻异物有向组合在相邻机位持续可见，真实检测框为其中 22 个提供有效互斥证据，使用真实框则为 46 个。实际双钟布局覆盖 8/30，双画布局覆盖 14/26。原单画布局另外出现 12 个无法对应标注物体的跨机位互斥信号。重复出现的误检也可能稳定跨视角，属于复核时必须保留的风险。[控制组结果](control_summary.json)
