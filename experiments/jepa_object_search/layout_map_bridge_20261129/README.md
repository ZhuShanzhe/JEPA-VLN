# 探索地图与局部观察位接口

局部选路使用同一份 0.125 米分辨率的地图。每格有三个状态，分别为未知、观测到的可通行地面和障碍。原生 MOST-Nav 使用 RGB 产生的 VGGT-SLAM 地图，HSSD 局部实验使用带度量深度的相机和相对里程计。模型只读取已观测区域。

| 数据来源 | 如何送入选路模块 |
| --- | --- |
| 原生 MOST-Nav | 从同一个探索地图快照提取占据栅格、当前位置、朝向和尺度。地图单位经换算后，以本次观察起点为原点，使用向右、向前的米制坐标。启用无真实位姿模式。地图尚未更新、对齐失败或跨楼层时返回未知。[原生适配器](most_layout_bridge.py) |
| 本地 RGB-D 和探索历史 | 将历次真实深度观测投影到机器人高度范围，更新已见地面和障碍。碰撞会在尝试前进的位置留下记录。上游已知障碍优先于单次深度的空闲证据。[地图更新](layout_memory.py) |
| 在线局部观察 | 用 `bind_local_inspection` 包装既有检查器，通过 `observe()` 和 `move(action)` 提供同一时刻的上游观察、局部 RGB-D 和相对里程计。外部地图随当前帧传给后续的局部重规划。每个实例请求建立独立绑定。[在线入口](layout_inspection.py) · [可运行示例](check_inspection_entry.py) |

局部接口固定为 192×192、90° 水平视场、平视、安装高度 1.31 米的度量 RGB-D。实际相机或原生任务若只提供单目 RGB，VGGT-SLAM 可以提供地图；局部模型所需的配准深度和图像仍要另行提供。该二维接口适用于单楼层，跨层需独立子图。

## 验收

- 从正在运行的真实建图服务只读取得包含 253 个不同关键帧的 RGB 几何快照，用原版 NavAgent 更新导航图。重采样后局部地图有 1,206 个可通行格和 897 个障碍格，676 个抽查位置与原生坐标换算完全一致。测试同时覆盖新碰撞、缺失地图或位姿、版本过期及跨回合隔离。[原生建图验收](live_map_audit.json)
- 在 30 条真实传感器记录中，有 27 条的原决策要前进。在这些动作的第一个落脚点加入模拟的上游障碍更新，27 条全部改变决策，14 条绕开该格，13 条转向观察或停止。把同一更新标记为过期，27 条均恢复原决策。这项对照只检验地图是否真正参与选路。[地图干预测试](route_injection_audit.json)
- 在 3 栋留出房屋各取首个冻结困难任务，运行 Habitat 闭环，经完整局部入口送入 71 份同步快照并执行 68 步。2 个请求结束于找不到有证据支持的观察位，1 个用完步数。此处上游栅格由同一房屋真实采到的深度和里程计生成，使用原生占据栅格结构。[完整入口测试](inspection_entry_audit.json)
