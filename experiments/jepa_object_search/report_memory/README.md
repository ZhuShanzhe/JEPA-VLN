# 多实例寻物的报告记忆与探索避重

MOST-Nav 在内部实例上记录已报告状态。原版时钟回合的第 65 步报对一个实例，第 88 步又报告了同一真实实例。原版画作的两次报告均超出有效范围。此适配器沿用原生实例登记、目标配额和报告动作，改进报告时机、相似实例辨认及后续的视角选择。[原版配对结果](../instance_view_confirmation/analysis/results.json)

| 阶段 | 行为 |
|---|---|
| 看到候选 | 保存通过原生审核的对象框、观察帧和拍摄位置。只要证据还不足，线索就保持可查，切换视角后可以继续核对。 |
| 决定报告 | 在当前画面定位整个对象区域并核对地图估计距离。历史单帧离目标较远时采用更紧的接近条件。两个相邻实例若都能解释当前同一块区域，暂缓报告。当前关键帧中各有独立登记框时，可分别确认。 |
| 写入记忆 | 发出报告先登记为待确认事务。下一步观测回传同一报告动作后才对该规范实例记账。重复回执只记一次，指令被替换或步号不连续时保留原线索。最后一步没有下一帧时，仍按待确认处理。动作回执只证明已执行，在线策略无法查询裁判得分。 |
| 保护其他实例 | 复用同一注册证据的候选可以去重。只有类别相同、距离接近或颜色相似时保留两条线索。同一画面中分离的框会阻止自动误合并，新候选仍可独立登记。 |
| 选择下一视角 | 将已报告视角绑定到可重新定位的地图关键帧。候选终点距旧观察位置不超过 0.55 米、朝向差不超过 25°、预计新见区域不足 25%，且还有其他可达选项时，路线最多扣 0.15 分。沿途 1.5 米内有待找实例，或有待判定、尚未定位的线索时，取消这项扣分。高价值路线仍可胜出。 |

## 模拟验证

| 同样的模拟输入 | 观察结果 |
|---|---|
| 依次请求远处报告 A、近处报告 A、原处重复报告 A、近处报告 B | 原版对不同实例报对 1/2，新版报对 2/2。两组使用相同图像和预设位置，得分在策略外计算。 |
| 新画面只有一幅画，两条相邻同款实例线索都能解释这块区域 | 暂缓认领第二实例。之后同一当前关键帧给出两个分离的登记框，两个实例可以各报一次。 |
| 已报告视角与一个新视角均可走 | 执行回执到达后，重复视角的轻微扣分使新路胜出。在旧路附近加入另一个待找实例，旧路恢复为首选。 |
| 发出报告后返回不同动作，或回执重复 | 动作被替换时实例仍可再次报告，重复回执不会重复记账。 |

39 项测试覆盖了真实代理的动作入口、报告账本、视觉匹配、同帧登记、实例关联和路线排序。测试使用合成 RGB、地图与动作，全程禁用网络连接。[测试回执](verification.json)

## 旧画面复核

沿用时钟和画作历史回合的原始登记框，三条登记记录都能生成对象模板。对照旧报告时的画面，时钟第 102 步的错误报告未通过新的外观检查，画作第 252 步的重复报告也未通过。但画作第 238 步原本得分的报告同样未通过。这个结果提示跨视角漏报仍是限制。固定图像只能检验外观条件，无法推算改动后整回合的成绩。[逐项记录](replay_appearance.json) · [复算程序](replay_appearance.py)

## 运行

服务器项目数据盘中的适配器入口为 `report_agent:ReportFrontier`。在项目根目录运行 `bash jepa_report_v19/check.sh` 即可重复禁网检查。实验环境使用原项目授权安装的 MOST-Nav、Habitat 与历史 JEPA 适配器。四个测试模块分别是 `test_chain.py`、`test_identity.py`、`test_appearance.py` 和 `test_exploration_memory.py`。
