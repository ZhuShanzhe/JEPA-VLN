# MOST-Nav 的视觉决策接口

MOST-Nav 的视觉决策模型可独立配置。工程验收使用同一张人为生成的测试卡，将红色方块从右侧移到左侧，每次只提供两个合法前沿。原版决策客户端接收图像、生成结构化动作，随后由原版动作校验器核对前沿编号。

| 模型标识 | 实测范围 |
|---|---|
| `gpt-5.6-luna` | 通过原生健康预检和图像调用。翻转目标后，动作从 `GOTO_FRONTIER(F_RIGHT)` 切换为 `GOTO_FRONTIER(F_LEFT)`。 |
| `gpt-4o-2024-11-20` | 通过原生健康预检和单张图像上的前沿动作校验，可作固定快照对照。 |
| `gpt-4.1-mini-2025-04-14` | 通过相同的健康预检和单张图像上的前沿动作校验，可用来评估较小视觉模型。 |

主基线与 JEPA 组固定相同模型、请求参数及消息格式，故障切换保持模型标识一致。对于 Luna，JSON 模式下用户消息缺少格式标记时统一补入 `Return JSON.`。保存供应商和响应型号以区分部署变化。中转响应给出的模型标识无法独立确认后端权重。

同一 Luna 接口还接受了 SCOPE 和 3D-Mem 四次真实调用。给两套程序一张自绘椅子图，SCOPE GOAT、3D-Mem GOAT 和 3D-Mem AEQA 的原生筛选函数均选出 `chair`。SCOPE 的原生前沿潜力解析器从响应读出四个数值，其中目标相关性为 4.5，综合潜力为 3.8。四次调用合计报告 1,567 tokens。

这些结果验证了图像输入和动作接口。模型对复杂室内场景的辨识、路线选择和多实例报告能力仍需通过冻结回合测量。原程序在推理服务中断时可能改用规则决策，此类回合在正式成绩中单列。
