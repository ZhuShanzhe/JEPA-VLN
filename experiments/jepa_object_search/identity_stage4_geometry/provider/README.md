# 复看时估计当前相机的几何

导航系统发起实例复看时，先检查映射器是否已有与当前 RGB 对齐的几何。额外的处理使用已建好的近邻关键帧，跟踪有三维地图点的像素，再用 3D–2D 对应估计当前相机位姿。用未参与求解的像素检查重投影误差，同时检查跟踪点在图像中的覆盖面积。只把有几何支持的深度点投到候选框中。

两臂的已建图关键帧走同一个原有接口。新增的非关键帧处理使用已知的 1.5 米相机安装高度与预测地面估计尺度，记录估计来源。达到覆盖和点数门槛后把两张图的几何交给既有跨视角实例核验器。缺少可靠输入时保留不确定状态。复看记录只在项目数据盘保存。

## 已录制在线输入的进一步检验

原生地图使用的相机投影带有非零的水平剪切项。保留这一项，并核对没有用于拟合的像素，可以恢复两组 55 项请求的来源地图读取。在求解相机姿态前先消除水平剪切，求解后再回到原始像素坐标检查误差。只修正内参、辅以特征匹配或连续跟踪，都未在这些输入上产生一对可送入身份头的几何。[内参核验](optics.py) · [校正后的配准](calibrated_tracking.py)

局部重建另有两套固定的时间窗。每套只读当时拍到的图像，将已有地图和局部子图中同一时刻的历史视角相连。第一张共享历史图用于对齐，第二张用于独立检查。再验证当前框内的深度在至少两个历史视角中都有颜色与深度支持。八步窗口和显式加入历史锚点的方案均在同一个开发请求中恢复了正确候选，其余 54 项没有获得可评分输入。[可复用的双锚核验实现](shared_anchor_pair.py)

两种窗口策略分别有 18、46 项进入重建。可复用接口在这些输入上复现了诊断程序的拒绝原因与候选选择；两次首例分数差均不超过 0.0000001。[输入约定与调用示例](PUBLIC_USAGE.md)

两条自主导航在同一个开发任务上分别出现 18、24 个有请求的动作步。每个动作步可能需检查多个来源，因此表中计数按来源帧和动作步去重。[两种窗口的完整分组计数](replay_summary.json)
