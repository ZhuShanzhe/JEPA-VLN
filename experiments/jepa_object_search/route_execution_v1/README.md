# MOST-Nav 探索观察位执行

从原版 MOST-Nav 的探索路径跟随器出发，在目标点附近继续走到选定的观察位，并补上末端转向。报告动作、目标发现中断、碰撞恢复和上层抢占沿用原有调度。主入口为 `point_executor.FocusViewMixin.start_focus_view(observation, actions, tag)`，在原生激活当前探索路径后调用。动作与相对坐标都来自当前选路器。

## 同一观察位的物理对照

来源是时钟、画作两个开发回合产生的全部 9 个选点。两个控制器每次从相同的历史位置和朝向开始，收到同一条候选折线。局部动作上限都是原计划动作数加 8，并受原回合 300 步剩余额度限制。当前位置由动作推算，视觉连续静止时交回恢复。不调用上层服务。真实物理位置与朝向仅在动作执行后用来评分。

| 终点条件 | 原版路径跟随器 | 精确视点跟随器 |
|---|---:|---:|
| 位置误差 ≤ 0.8 米 | 5/9 | 5/9 |
| 位置误差 ≤ 0.25 米 | 0/9 | 4/9 |
| 位置误差 ≤ 0.125 米且朝向误差 ≤ 15° | 0/9 | 4/9 |
| 合计实际动作 | 119 | 170 |

原版 7 次在内部认定抵达、2 次因画面连续静止而退出。原版探索航点使用 0.8 米到达半径，缺少末端观察朝向要求。严格阈值下的进步伴随更多动作。历史整机 1/9 的观察位抵达数还包含真实上层和地图更新，与上述控制器重放分开报告。[九个配对结果及源日志哈希](paired_geometry.json)

在终点评分之外，单独查询仿真行走网格，2 个候选离同一连通区域最接近的网格点水平仍有 0.34、0.40 米，另外 7 个的投影差小于 0.125 米。这 7 个中有 4 个抵达；3 个在碰撞或滑移后未抵达。这一网格检查从不参与动作选择。

对上述 3 个困难视点，使用完整网格求出动作序列，恢复原始位姿后在 Habitat 逐动作验证。在分别为 24、23、32 步的局部额度内，构造出的路径分别用了 **19、18、19 步**，实际终点误差为 **6.2、6.2、3.8 厘米**，最终朝向均正确。三例都存在预算内解。在线系统可用的地图、定位和绕行能力还无法稳定找出这样的路线。[动作级可行性记录](oracle_budget.json)

## 真实 RGB 建图下的局部绕行

复测以上 3 个物理可达的困难观察位。独立原生 VGGT-1B 服务读取决策前的历史 RGB 和决策后实际移动所得的新 RGB；无付费图片服务。沿用原始基准允许的 GPS 位移作地图尺度标定，路线控制未读取仿真器的当前位置、朝向、完整行走网格或目标位置。发生较大定位修正或运动停滞时，从最新估计位姿在当前已观察的占据栅格内运行原生 A*。一次修正后的单个几何关键帧只能提供定位证据，仍需独立物理计分。

| 方案 | 三次物理终点误差（米） | 精确抵达数 |
|---|---|---:|
| 只接受地图内连通的完整通路 | 2.52、2.27、2.27 | 0/3 |
| 补走已观察的可达中间位置，最多两次 | 1.56、2.26、1.66 | 0/3 |
| 选择能看向未知区域的边缘位置，排除重复中间点，最多四次 | 1.18、2.06、2.53 | 0/3 |

边缘方案分别实走 24、23、25 步。前两例耗尽局部额度，第三例已做完四次重规划。它在第一例继续靠近，在另两例没有形成可靠改进，因此中间点补救保留为显式配置 `enable_focus_staging=True`。默认遇阻时只接受有近期地图定位支持的完整可行绕行，无法证实时交回原探索器。只有当前帧的地图定位符合视点要求，才会记录为由地图定位确认的抵达。[直接绕行](live_full_history.json) · [中间点](live_staging.json) · [边缘视角](live_edge.json)
