# HM3D 多路线选路验证

实验复用 MOST-Nav 两个已验收回合，一个寻找时钟，一个寻找指定的风景画。在原版控制器激活探索的 12 个时刻分别恢复当时的位置、相机方向、已观察到的画面和报告记忆。各路口独立运行，候选来自当时的地图，扫描和动作由 Habitat 重新执行。对照从同一起点沿原生路线行走。模型只能看到当前及过去的 RGB、历史动作、任务描述和候选动作。仿真器位置用于检查起点与测量路线分歧。

| 文件 | 用途 |
|---|---|
| `run_replay.sh` | 在已有 MOST/HM3D 环境中启动全部验证，核对源码哈希，私有输出写到数据盘的新目录 |
| `replay_junctions.py` | 重建原始观测历史，让正式评分器在自然候选中选择。另用固定评分结果检验宿主能否执行第三、第四条路线 |
| `check_safety.py` | 通过原生公开决策入口，在实际仿真运动中模拟主动报告或结束请求，检查抢占 |
| `summarize.py` | 从完整验收记录中生成聚合结果，区分位置分开、仅朝向分开与保留原生路线 |
| `public_summary.json` | 两组任务的聚合结果，强制选择与模型自主选择分别统计 |

运行 `bash checks/run_replay.sh`。脚本默认从自身路径定位项目，也可读取 `NAV_ROOT`。本地需已有获准使用的场景、对应历史日志和预训练模型。验证过程中，操作系统会阻止评测进程及评分子进程建立 IPv4/IPv6 网络连接。

每个路口在模型路线和原生路线首次发出不同动作时比较位姿。位置差超过 5 毫米计为位置分开，位置差不超过 5 毫米但朝向差超过 1° 计为仅朝向分开。历史建图与上层付费决策复用已有记录。这里衡量的是选路器和执行器对局部路线的改变，寻物成功率和报告质量需由完整回合测量。
