# MOST-Nav 多候选探索接口

运行入口为 `variable_agent:VariableFrontier`。宿主从 MOST 已成功激活的探索决策取得原生前沿列表。目标报告、停止、绕障和其他原生高优先级动作继续使用 MOST 与 V14 的执行逻辑。

| 文件 | 用途 |
| --- | --- |
| `variable_routes.py` | 在扫描后的剩余步数内整理所有可区分的原生路线。 |
| `variable_agent.py` | 读取前沿、调度四个真实扫描动作、调用评分器并交接给 V14。 |
| `delayed_forks.py` | 识别远端分岔，跟随原生路线行进后用当前地图重新验证分支。 |
| `variable_worker.py` | 读取按时间排序的实际观测，更新回合记忆和已报告方向，批量请求证据预测。 |
| `variable_policy.py` | 结合单位步数证据率、已访问比例、碰撞与目标线索记忆为每条路线评分。 |
| `check_variable.py` | 验证可变数量和长度、重复路线、剩余预算、候选顺序与并列行为。 |
| `check_deferred.py` | 调用 MOST 的真实 PathFollower，在合成长廊中验证延迟选择和中断。 |

任一决策点至少需要两条能在观察范围内走向不同位置的路线。候选数量取决于原生规划器当前给出的前沿。每条路线使用进入终点、达到剩余预算或走满模型的 24 步预测窗口之前的真实动作。根据每次前进时的朝向识别空间分支。单纯在原地转身、重复地面路径和只在窗口外分岔的路线都无法在当前决策点提供独立的可执行选择。

原生选择排首位并在完全同分时优先。所有路线采用同一公式。在线记忆结合历史碰撞、当前位置附近的访问记录和已经看到的目标线索。模型将每条路线在其实际长度内获得新证据的概率换算为统一六步尺度参与比较。线索稀少且剩余步数充足时，探索项提高未访问路线的分数。日志同时保存整条前缀的证据概率、六步证据率、记忆项、探索项、实际长度以及动作交接回执。

若多条通向不同远端的原生路径共享前 24 步，几何投影仅用于判断何时再看一次。原生跟随器实际走过共用段，适配器逐步确认行动及碰撞，并在靠近分岔后检查当前位姿与地图。只有新地图上仍有可达分支才扫描。评分前通过原生 A* 再次验证，从新的真实视角预测接下来的至多 24 步。回环、更换前沿、碰撞恢复、报告抢占或剩余预算不足都会结束本次延迟判断。

在部署环境运行 `python -B check_variable.py` 即可执行无 API 的接口单测。
